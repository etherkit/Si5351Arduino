# Debatable expectations (decide before finalising the fix)

For these items the tests only check the **policy-neutral spec invariants** and accept any listed option. The machine-readable copy is the `debatable` block in `v231_acceptance.json`.

| ID | Tests | Question | Options | Test currently accepts |
|---|---|---|---|---|
| D1 | A01, A02 | `set_freq(f < 18.454 kHz)` on CLK6/7 (10 kHz, 15 kHz). The lowest legal output is 600 MHz/254/128 ≈ 18454 Hz | (a) reject: ret 1, no writes (like the CLK7 non-integer reject); (b) clamp to the CLK6/7 minimum and return 0 (like the CLK0-5 clamp); (c) clamp and return a non-zero code | (a), (b) or (c), provided reg90 is even 6..254, `pllb_freq` is 600..900 MHz and the output is ≥ 18454 Hz. **Gotcha:** `SI5351_CLKOUT67_MIN_FREQ` truncates to 18454. 254×128×18454 Hz = 599.98 MHz < VCO_MIN, so clamping to the constant itself trips the `a += 2` path again and writes MS6 = 256 → 0x00. Round up (18455) or guard `a += 2` beyond 254 |
| D2 | A09, A10 | `set_freq(0)` on CLK6/7. Today it crashes with a peer set; without a peer it writes MS6_P1 = 0 | (a) return 1, no writes; (b) treat 0 as "disable output"; (c) mirror CLK0-5, which today writes a 500 kHz MS and enables the output | anything without a crash or an invalid reg90/91 value. Consider making CLK0-5 consistent too (it is not locked) |
| D3 | A11-A13 | Requests > 200 MHz on CLK0-5 (210/225 MHz; `SI5351_MULTISYNTH_MAX_FREQ` is 225 MHz) | (a) clamp to 200 MHz (DIVBY4, PLL 800 MHz); (b) reject with ret 1 | either. For `set_freq_manual`, clamping `freq` is not enough: DIVBY4 outputs PLL/4, so 900 MHz still gives 225 MHz. The fix must reject or refuse DIVBY4 when pll ≠ 4×freq (DEV-06 overlap) |
| D4 | A14-A16 | `set_freq_manual` with an illegal MS ratio (5, 6.667, 7) | (a) return 1 without writing MS; (b) round to a legal ratio; (c) write, but return non-zero | (a) with no MS0 block written, or any legal written ratio. Open sub-question: may a rejected call still write the PLL? 1ddd43e writes the PLL first |
| D5 | A22 | `init(SI5351_CRYSTAL_LOAD_0PF)`: XTAL_CL = 00b is reserved | (a) map to 6 pF (01b); (b) leave the 10 pF default (11b); (c) deprecate/remove the constant (API change) | any XTAL_CL ≠ 00b with bits 5:0 = 010010b |
| D6 | A25 | 5 MHz reference (DEV-13). PLL input range is 10-40 MHz, and no legal feedback ratio exists for 600-900 MHz | (a) `init()`/`set_ref_freq` reject < 10 MHz. Careful: `xtal_freq` = 0 then divides by zero in `pll_calc`; (b) recompute `a` after the clamp → ratio 90, VCO 450 MHz (still out of spec); (c) never write an out-of-range feedback block | any policy that writes no PLL block with a ratio outside 15..90. The validation prototype used (b), which passes the test but leaves the VCO at 450 MHz: flag it if chosen |

Also worth a decision, though not a test: should A08's reject (`set_freq` returns 1 when the CLK6/7 peer is set and no legal MS×R exists) also cover the case where `pllb_freq % freq == 0` but the R divider makes it non-integer? It is the same code path, and A08 is exactly that case.
